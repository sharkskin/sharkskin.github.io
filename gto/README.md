# GTO 德州扑克 · 单挑 / 多人桌练习

一个用来**学 GTO 策略**的德州扑克练习工具。支持**单挑（2 人）**与**多人桌（3 / 4 / 6 人）**。和 AI 对战、实时看教练建议、打完复盘每一手、还能把牌局分享给别人。

## 快速开始

直接双击 `index.html` 用浏览器打开即可（推荐 Chrome / Edge）。

如果需要手机访问，在本目录起一个静态服务：

```bash
python -m http.server 8080
# 然后手机浏览器访问 http://<电脑局域网IP>:8080
```

## 功能

| 模块 | 说明 |
|---|---|
| **牌桌** | 100BB 起始筹码，可选 **2 人（单挑）/ 3 / 4 / 6 人桌**，按钮位每手轮转。支持弃牌 / 过牌 / 跟注 / 下注 / 加注 / 全下，带快捷尺度（1/3、1/2、2/3、1 池、1.5 池）。多人桌自动处理**分池（side pot）**与未跟注退还 |
| **GTO 教练** | 实时给出每个行动的**频率分布**与 EV、你的胜率、底池赔率、手牌描述、决策理由；多人桌额外标注所处**位置**（UTG/MP/CO/BTN/SB/BB）与身后还有几人未行动。可一键关闭进入「考试模式」 |
| **范围表** | 13×13 起手牌矩阵，色块宽度 = 该动作的频率。**单挑**：SB 开池 / BB 防守 / 对 3bet / 对 4bet；**多人桌**：UTG / MP / CO / BTN / SB 五个位置的开池范围。点击任意手牌看详细频率 |
| **复盘** | 逐手逐决策点对比 GTO 分布，标注主流打法、EV 最高选项、尺度偏差；汇总 VPIP / PFR / 摊牌率 / 攻击因子 / EV 损失 / 决策质量分布。多人桌会列出各家底牌 |
| **回看** | 逐步播放任意一手牌（发牌 → 每条街 → 每个动作 → 摊牌），复现当时的牌面、底池、每座位投入量与 GTO 建议 |
| **分享** | ① 分享码（压缩后 base64，可在任意设备导入回看，含人数信息）② 文字战报（可直接粘到微信，列出各座位底牌与位置）③ 导出 / 导入 JSON 文件 |

设置项：**牌桌人数**（2 / 3 / 4 / 6）、AI 难度（新手 / 标准 / GTO）、起始筹码、决策速度、教练开关、是否显示 AI 手牌。
所有设置与牌局记录存在浏览器本地，关掉再打开会自动恢复。切换人数会开新的一局（不同人数的牌局记录无法混着继续）。

## GTO 引擎原理

这不是完整求解器，而是面向教学的**近似 GTO** 引擎。三个层次：

**1. 预翻牌 — 真实胜率驱动**
用蒙特卡洛离线预计算 169 种起手牌对随机手牌的胜率（`tools/gen-preflop-table.js`，每个组合 4 万次模拟，结果写入 `js/preflop-table.js`）。
校准结果与公认值一致：AA 85.2%、KK 82.5%、QQ 79.9%、22 50.4%、72o 33.9%。
范围定义即为「按胜率排名 + 牌型可玩性修正」的加权函数，例如大盲面对开池防守约 80%、3bet 约 20% 且极化。

**2. 翻牌后 — 多因子联合决策**
每个行动点计算：

- **胜率**：对**对手估计范围**做蒙特卡洛（而非对随机手牌），范围由对手整条动作序列逐步收窄（`RangeTracker`）
- **底池赔率**：决定跟注是否保本
- **牌面纹理**：同花可能度、顺子连接度、成对与否、高低牌面 → 谁拥有范围优势
- **位置与 SPR**：有利位置更主动，短筹码更倾向全下
- **EV 估算**：每个候选行动算 `foldEquity × pot + (1-foldEquity) × 被跟注收益`，并计入被加注的风险

**2b. 多人桌 — 位置与多人底池修正**

- **位置模型**：按人数计算 UTG / MP / CO / BTN / SB / BB 的相对位置，每个位置有自己的**开池宽度阈值**与**加注尺度**（UTG 约 18% / 2.6bb → BTN 约 51% / 2.2bb，实测 RFI 梯度 15.8% → 26.9% → 36.0% → 50.0%）
- **可玩性修正**：多人桌不能只按单挑胜率排序 —— 同花连牌、中小对子在多人底池里的实际价值远高于纯胜率排名。引擎用 `playScore` 对排名做结构修正后再切范围
- **多人胜率**：`calcEquityMulti` 对多个对手范围同时做蒙特卡洛（AA vs 1 家 84.6%、vs 2 家 74.2%、vs 4 家 56.4%）
- **弃牌概率幂次化**：多人时「所有人都不弃牌」的概率按 `base^对手数` 收缩，下注的弃牌权益明显低于单挑
- **底池收紧系数**：每多一个未弃牌对手，加注 / 跟注 / 主动下注频率分别乘 0.70 / 0.86 / 0.80 的幂次 —— 多人底池里诈唬要少、价值要更实在
- **分池结算**：`buildPots` 按各家投入切出主池与边池，逐池独立判定赢家；未跟注的超额部分原路退还，且**不计为「赢」**

**3. 混合频率输出**
输出的核心不是「唯一正确答案」，而是**频率分布**（例如「跟注 72% / 加注 20% / 弃牌 8%」）。这正是 GTO 的精髓——用随机化让对手无法从你的动作反推牌力。
AI 按同一套频率抽样行动，因此**你面对的对手打的确实就是它教你的那套策略**，学习闭环是自洽的。

> 注意：预翻牌范围是经过校准的近似值，翻牌后的 EV 模型做了工程简化。它能帮你建立正确的决策框架（赔率意识、范围思维、混合频率），但不能替代 PioSOLVER 等专业求解器的精确解。

## 复盘判定逻辑

GTO 里「EV 最高的行动」常常**不是**「最常出现的行动」。所以复盘判定失误时看的是：

- 你的选择是否落在 GTO 的合理分布内（频率够高）→ 主流打法 / 可选分支
- 行动方向是否偏离（该弃牌却跟注）→ 按 EV 损失分级：小偏离 / 偏离 / 严重偏离
- 尺度是否偏离（方向对了但下注量差太多）→ 尺度偏离

只有真正的偏离才计入 EV 损失统计。

## 迁移到微信小程序

逻辑层已按此目标设计——`poker-eval / preflop-table / equity / gto / engine / recorder` **全部不依赖 DOM**，可原样搬进小程序。

迁移要点：

1. **模块化**：把这 6 个文件末尾的 `root.XXX = {...}` 改成 `module.exports = {...}`，其余代码不动。
2. **存储**：`localStorage` → `wx.setStorageSync`；`Recorder` 的分享码逻辑保留（小程序也支持 `CompressionStream`，不支持时自动降级为未压缩 base64）。
3. **界面**：`ui.js` 需重写为 WXML + WXSS。样式变量（`css/style.css` 里的 `:root`）可直接搬到 WXSS。
4. **分享**：`onShareAppMessage` 直接返回分享码作为 query 参数，好友点击进入即自动导入回看——这是小程序比 H5 更有优势的地方。
5. **注意**：分享码较长（约 1.6–6KB），超过小程序 path 长度限制时可改为上传到云开发数据库换取短 ID，或让用户手动粘贴分享码。

## 已知限制

- 最多 6 人桌；9-max 的 GTO 范围复杂度高一个量级，暂不支持。
- 多人桌预翻牌只建模了「开池 / 对开池 / 对 limp / squeeze 风险」这条主干，没有建模跟注池（cold call）后的多人翻后范围细分。
- 翻牌后策略是启发式 + EV 近似，非求解器精度。
- 分享码体积较大（单挑约 1.6KB、6 人桌 5KB+），不适合做短链接。
